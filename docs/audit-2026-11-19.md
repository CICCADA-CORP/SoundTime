# SoundTime audit, 19 November 2026

The review started from commit `e660472` on `main`. The issue register records the changes proposed for release. [GitHub issues](https://github.com/CICCADA-CORP/SoundTime/issues)

| Issue | Finding and outcome |
| --- | --- |
| [#4](https://github.com/CICCADA-CORP/SoundTime/issues/4) | The PostgreSQL aggregate type fix was already present. The integration test exercises the storage status handler. A separate PostgreSQL check confirmed that the sum decodes as a bigint above the 32-bit limit. Storage totals now exclude remote P2P tracks. |
| [#5](https://github.com/CICCADA-CORP/SoundTime/issues/5), [#11](https://github.com/CICCADA-CORP/SoundTime/issues/11) | Manual and scheduled scans reconcile moved and missing files, preserve track references for identified moves, and repair identifiable historical duplicates. An empty source requires an administrator to confirm cleanup for that source. |
| [#6](https://github.com/CICCADA-CORP/SoundTime/issues/6) | Single and batch uploads check SHA-256 of the stored audio, including the FLAC output of AIFF conversion. Duplicate submissions return HTTP 409 or a per-file batch error. Missing files with a known hash can be restored under their original track ID. |
| [#7](https://github.com/CICCADA-CORP/SoundTime/issues/7) | The Docker Compose overrides mount SMB and NFS shares read-only. Uploads and generated cover art stay on writable local storage. See the [deployment guide](deployment.md). |
| [#10](https://github.com/CICCADA-CORP/SoundTime/issues/10) | Participating nodes register at the same opt-in rendezvous and obtain peer IDs, including when they use a relay. Operators can host the rendezvous on a SoundTime backend. See [P2P networking](p2p-networking.md). |
| [#12](https://github.com/CICCADA-CORP/SoundTime/issues/12) | The author asks about the future of the project. Maintenance plans and any public reply are for the project maintainer to confirm. |

## Dependencies

| Check | Original lockfile | Updated lockfile |
| --- | ---: | ---: |
| npm audit, all dependency types | 23 affected packages, including 2 critical | 0 |
| RustSec, package and vulnerability advisory matches | 88 | 2 |

The Rust audit used cargo-audit 0.23.0 and the 19 November advisory database. The table counts matches for individual locked package versions. Yanked releases were outside this check. [RustSec database snapshot](https://github.com/RustSec/advisory-db/tree/7133866a6b44d6d3e1994ae6a48a296553c3c3da)

The two remaining matches are `rsa 0.9.10` through the optional SQLx MySQL driver and `libsqlite3-sys 0.30.1` through the optional SQLite driver. The Linux x86-64 and ARM64 server builds select the PostgreSQL driver. Their normal and build dependency graphs exclude both affected crates with Redis enabled. [RSA advisory](https://rustsec.org/advisories/RUSTSEC-2023-0071.html) · [SQLite advisory](https://rustsec.org/advisories/RUSTSEC-2026-0459.html)

RustSec also reports nine memory-soundness warnings for `heapless 0.7.17` and six maintenance warnings across the lockfile. The P2P stack enables `postcard 1.1.3` with its default `heapless` feature, which requires the 0.7 series. The nine advisories are fixed in `heapless 0.9.4`. This remains an upstream dependency constraint in both Linux builds. [Heapless advisories at the audited revision](https://github.com/RustSec/advisory-db/tree/7133866a6b44d6d3e1994ae6a48a296553c3c3da/crates/heapless)

To reproduce the dependency checks, run `npm ci` and `npm audit` in `frontend`, then `cargo audit --no-yanked` in `backend`. Inspect the server graph for each target with `cargo tree --locked -p soundtime-server --features redis --edges normal,build --target x86_64-unknown-linux-gnu` and the equivalent `aarch64-unknown-linux-gnu` command. A newer advisory database may produce different counts.

## Local verification

- The Node.js 24 frontend passed type checking, its production build and all 606 unit tests. Coverage reached 92.79% of lines and 78.74% of branches. The production server returned HTTP 200 for `/`, `/login` and `/tracks` after installing its runtime dependencies. npm reported a deprecation for `lucide-svelte` and names `@lucide/svelte` as its successor.
- Rust 1.97 passed formatting, Clippy with warnings treated as errors, all 768 workspace tests, and the separate PostgreSQL integration test. The Redis-enabled server built successfully. Cargo reports a future-compatibility warning in `proc-macro-error2 2.0.1`, a transitive dependency of the SeaORM macros.
- Docker Compose rendered the default, SMB, NFS and combined configurations. The resolved mounts give the backend read-only access to the shares and retain its writable music volume. A live NAS mount and a Docker image build remain unverified because this machine had no connected NAS or running Docker daemon.
- The installer generated credentials with mode `0600`, preserved them on a second run and probed the backend's `/healthz` endpoint.
- A fresh PostgreSQL 18 database with pgvector 0.8.1 applied all 34 migrations. The live server accepted one of two simultaneous identical uploads and returned HTTP 409 for the other. It reported both duplicates in a batch, returned storage statistics, preserved the track ID when its file moved, and protected the final missing track on an empty source.
- Two signed identities discovered one another through the HTTP rendezvous. Direct QUIC connections between the old and new transports worked in both directions on loopback. A test store retained tags, inlined data and external blobs during upgrade. Restoring its pre-upgrade archive made them readable with the old binary. An existing volume must be backed up before its first upgrade. Public relay connectivity remains unverified. [P2P upgrade and rollback](p2p-networking.md#upgrading-the-p2p-store)
